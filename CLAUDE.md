# PICSL website: notes for Claude Code

Jekyll site on the Greene Lab Lab Website Template, deployed to GitHub Pages from `main`.
See README.md for where content lives.

## Workflow

- Work on a branch, never on `main`. When the user is done, commit and open a pull
  request with `gh pr create`. The PR gets a preview link automatically.
- Preview locally with `bundle exec jekyll serve` (http://localhost:4000).
- Before committing, build with `bundle exec jekyll build` and check internal links:
  `bundle exec htmlproofer ./_site --disable-external --no-enforce-https --ignore-missing-alt --allow-missing-href --ignore-files "/publications/"`.
  To check a page visually, take a headless Chrome screenshot and look at it.
- `_data/citations.yaml` is generated by the `update-citations` workflow. Don't edit it.
  If it conflicts during a rebase, keep the version from `origin/main`.

## Content conventions

- Members: `_members/<slug>.md`. Alumni get `role: alumni` and `group: alum`. Store photos
  in `images/members/<slug>.jpg`.
- Photos: crop to a square centered on the face (the site shows them in a circle), and
  re-save without EXIF metadata, which can include GPS location.
- Verify IDs before using them (ORCID via the ORCID API, etc.). Other lab websites have
  had wrong ORCID and Google Scholar IDs.
- Research posts: `research/<slug>.md` with `layout: post`, `date`, and `author:` set to
  the PI's member slug. Add a matching card to `_data/projects.yaml` (tag `research`,
  newest first). Write only from the abstract; don't add claims it doesn't support.
  Link coauthors who have member pages.
- Figures from papers: reuse only when the license allows it (check Crossref or Europe
  PMC). Credit the figure and license in the caption. Don't crop "ND" licensed figures.
  Otherwise draw a simple SVG diagram in the site colors (#16567a, #00a8d8) and caption
  it as an illustration.
- Links in Markdown can be root-relative (`/images/...`); `_plugins/baseurl.rb` adds the
  base path when the site is served from a subpath.
